# PLC Browser IO — WebSocket bridge for S7‑1500 (TIA V18 / PLCSIM Advanced)

A single‑source SCL bundle that turns an S7‑1500 into an **RFC 6455 WebSocket
server**. A browser connects to `ws://<PLC_IP>:8082` and exchanges typed I/O with
the CPU every cycle — no gateway, no external runtime, just one CPU and one
`.scl` file.

The transport is **generic**: it ships whatever bytes are in the output image and
receives into the input image, **sized automatically** from the array lengths.
You describe the dataset in the webpage; the webpage generates the matching
struct + pack/unpack source that you drop in beside `PLC_Browser_IO.scl`. Change
the data → regenerate that one piece → re‑import. The engine never changes.

## 2. Block map — what to edit and what never to touch

Everything lives in `PLC_Browser_IO.scl`. Two groups:

**FIXED — the reusable engine (never edit):**

| Block | Job |
|-------|-----|
| `FB_WS_Server` | WebSocket engine: HTTP‑101 handshake, frame codec, `TRCV`/`TSEND`. |
| `FB_WS_Bridge` | Top wrapper: **auto‑sizes** the transfer, cycles the outgoing watchdog, supervises the incoming one. |
| `FC_WS_SHA1`, `FC_WS_Base64`, `FC_WS_FindKey`, `FC_WS_BuildAccept`, `FC_WS_ParseFrame`, `FC_WS_BuildFrame` | Crypto + RFC 6455 codec. |
| `FC_WS_SelfTest` | Offline unit tests for the crypto/codec (call once from a watch table). |
| `UDT_WS_Frame`, `UDT_WS_Config`, `UDT_WS_Status` | Engine types + live diagnostics. |

**SHAPE‑SPECIFIC — generated by the webpage (replace when the dataset changes):**

| Block | Job |
|-------|-----|
| `UDT_App_Inputs` / `UDT_App_Outputs` | Typed, named view of your data. |
| `FC_WS_MapInputs` / `FC_WS_MapOutputs` | Pack/unpack between the typed view and the wire image (handles little‑endian). |
| `DB_WS_Input.Raw` / `DB_WS_Output.Raw` | Wire‑image size. |

`DB_WS_Bridge` (instance) and `OB "Main"` (example wiring) round it out.

> **Block numbers:** after *Generate blocks from source*, set these blocks to the
> **8080+** range in their properties so they don't clash with your program
> (TIA assigns free numbers automatically otherwise; calls are symbolic either way).

## 3. Data flow

```
   browser  --input frame-->  DB_WS_Input.Raw  --FC_WS_MapInputs-->  DB_WS_Input.App   (your logic reads)
   browser  <-output frame--  DB_WS_Output.Raw <-FC_WS_MapOutputs--  DB_WS_Output.App  (your logic writes)
                                     ^
                                FB_WS_Bridge  (auto-sized, watchdogs)
```

Per scan, `OB "Main"`:
1. `FC_WS_MapOutputs` packs `DB_WS_Output.App` → `DB_WS_Output.Raw`.
2. `FB_WS_Bridge` ships `OutRaw` and receives into `InRaw` (length taken from the
   arrays via `UPPER_BOUND` — nothing hard‑coded).
3. On fresh data, `FC_WS_MapInputs` unpacks `DB_WS_Input.Raw` → `DB_WS_Input.App`.
4. **Your control logic** reads `DB_WS_Input.App.*` and writes `DB_WS_Output.App.*`.

Byte 0 of each image is a **watchdog**: the bridge cycles the outgoing one while
linked, and raises `WatchdogError` if the incoming one stops changing for
`WatchdogScans` scans.

## 4. Commissioning (once)

1. **Add the TCP connection manually** — it is *not* created from code
   (`TCON`/`TDISCON` don't work on PLCSIM, see §7), so you configure it once by hand:
   - Open the **Devices & networks** editor → **Network view** → **Connections**,
     pick **TCP connection** in the dropdown, then drag from the CPU to the CPU
     itself (a local, unspecified‑partner connection). Or configure it inline from
     the `TRCV`/`TSEND` block's **Properties → Configuration → Connection parameters**.
   - Set **Establishment: passive** (the CPU is the server and listens), **Partner:
     unspecified** (any browser may connect), and a **local port**.
   - **Local port can be any free port.** The example uses **8082**. Avoid ports the
     CPU already occupies — **`102`** (ISO‑on‑TCP / S7 communication & PG/HMI) and
     **`80` / `8080`** (the CPU web server) are taken; pick something else if 8082
     clashes on your setup. Whatever you choose must match the `ws://<PLC_IP>:<port>`
     the browser connects to.
   - Note the connection's **Local ID** (TIA's default for the first connection is
     `16#0100`) — you'll wire it into `OB "Main"` in step 3.

   This CONFIGURED connection driven by **basic `TRCV` + `TSEND`** is the *only*
   transport that works on PLCSIM Advanced (see §7).
2. **Import** `PLC_Browser_IO.scl` as an external source →
   *Generate blocks from source* → *Compile* → download, PLC in RUN.
3. In `OB "Main"`, set `ConnectionID` to the connection's Local ID.
4. Point the browser / probe at `ws://<PLC_IP>:8082`.

## 5. Test without a browser

`ws_probe.py` is a full WebSocket client: it does the handshake by hand, floods
input frames at browser cadence, decodes the returned output map, and prints a
verdict. Pure standard library.

```bash
python ws_probe.py                 # 8 s run against 192.168.0.2:8082, then a verdict
python ws_probe.py --seconds 20    # longer
python ws_probe.py -v              # hex-dump every frame
python ws_probe.py --handshake-only
```

- **PASS** — bidirectional link works, output watchdog cycling.
- **FAIL (0 output frames)** — the probe tells you exactly which counter in
  `DB_WS_Bridge.diag` to read next.

A healthy run pushes **hundreds of frames/second** each way.

## 6. Changing the dataset — the TIA web generator

Use the **S7‑1500 / TIA Portal page**: `webpage/s7-1500.html` (open it via a local
server — see §5's note about `file://`). It is the Siemens counterpart of the
CODESYS page and shares the same WebSocket engine (`plc-core.js`), so the browser
side stays identical.

1. Open `s7-1500.html`, press `F9`, edit the **INPUTS / OUTPUTS** signal lists
   (add/remove/rename fields, set types). The watchdog byte is added automatically.
2. Go to the **EXPORT SCL** tab → **Generate PLC_Browser_IO.scl** → **Download**.
   This is a *complete, import‑ready* file: the fixed engine **plus** your dataset
   baked into `UDT_App_*`, `FC_WS_Map*`, and the `DB_WS_*` sizes.
3. In TIA: add it as an external source → *Generate blocks from source* → compile →
   set `ConnectionID` in OB `Main` → download. That's it — "import and go".

The generator (`webpage/s7-codegen.js`) emits the shape‑specific blocks and splices
them into the engine template (`webpage/s7-engine-template.js`, produced by stripping
those blocks from this monolith). The layout it produces is guaranteed to match the
browser's packing:

**Wire contract:**
- Byte order on the wire is **little‑endian** (browser native). The generated map
  functions convert to/from S7 big‑endian per field — the Siemens‑specific part
  (a CODESYS target would differ).
- Field order = **watchdog byte first**, then fields by descending alignment
  (4‑byte → 2‑byte → 1‑byte / bits), with S7 alignment padding.
- Strings are C‑style: *N* chars + one `NUL`, i.e. `Array[0..N] of Char` (not S7 `STRING`).


The included example matches `webpage/config/simulation_project.json`
(39‑byte input image, 59‑byte output image) so it runs out of the box.

## 7. Why it's built this way (hard‑won constraints)

Three PLCSIM/TIA traps this design deliberately avoids — each cost real debugging:

- **Transport:** `TRCV_C`/`TSEND_C` (compact) hold a permanent `16#80C4` on PLCSIM
  and never complete the handshake. A **configured connection + basic `TRCV`/`TSEND`
  by ID** is the only thing that works. No programmatic `TCON`/`TDISCON`.
- **`CASE` labels:** in external‑source SCL, local `CONST` identifiers used as `CASE`
  branch labels compile but **never match at runtime**. The engine uses numeric
  literal labels on purpose — do not "clean this up".
- **`TSEND` re‑arm:** `TSEND` starts a job only on a **rising edge of `REQ`**. Under
  continuous traffic, re‑asserting `REQ` right after `DONE` keeps it high forever
  and the block sticks at `16#7000` (nothing sends). The engine forces **one
  `REQ=0` scan between sends** (`txGap`) to guarantee a fresh edge.

---

## 8. Timing

`OB "Main"` is OB1 (cyclic) in the example. For a steadier ~10 ms browser cadence,
call the same body from a **cyclic‑interrupt OB (OB30 @ 10 ms)** instead. Each frame
takes ~2–3 scans (send + one re‑arm scan), which is still hundreds of frames/second
on OB1 — far above the browser's needs.

## 9. Live diagnostics

Watch `DB_WS_Bridge.diag` (type `UDT_WS_Status`) online:

| Field | Meaning |
|-------|---------|
| `uiState` | `0` idle · `20` handshake‑recv · `30` handshake‑send · `40` connected · `60` disconnect |
| `xHandshakeDone`, `xClientConnected` | link up |
| `udiRxFrames`, `udiTxFrames` | frames received / sent |
| `udiReconnects`, `udiProtocolErrors`, `udiTransportErr` | health counters |
| `wTrcvStatus`, `wTsendStatus` | live OUC status words |
| `asTrace[0..15]` | rolling human‑readable event log (newest = `asTrace[(uiTraceIdx-1) MOD 16]`) |
